# 数据来源与合规说明

依据大赛 FAQ Q18、Q41（数据合规）。

| 数据 | 来源 | 是否含真实信息 |
|---|---|---|
| 320 条工单、3 个岗位画像 | 作者编写的固定种子生成器 `scripts/generate_demo_data.py`（seed 20260909）按模板生成 | 否。电厂、机组、设备编号、型号、人员均为虚构；厂家名称只用于匹配词典，不代表相关厂商发生过这些事件 |

| 设备—部件知识库 `data/knowledge/components.json`（70 个部件、180 个叫法） | 作者与 AI 编程助手按系统整理的通用专业常识，未参考真实电厂资料 | 否，仅为术语对照 |
| 两批困难工单留出题 `hard_cases_holdout.json`（12 条）、`hard_cases_holdout2.json`（12 条） | 作者与 AI 编程助手手工编写，分别在 v2 提示词修改前、知识库接入前编写并提交（以 git 提交时间为证），用于独立检验 | 否 |
| 23 条困难工单 `data/synthetic/hard_cases.json` | 作者与 AI 编程助手于 2026-11-01 手工编写，刻意选取规则评分容易判错的写法（设备俗称、设备词只作地点、设备字段填错、等级低估、其他机组）；每条标注真实设备与等级 | 否。设备描述是演示文案，不是操作规程 |
| 专工盲评表 `data/blind_review/专工盲评表.xlsx` 与答案键 `key.json` | 由上述三批困难工单生成；答案键中的系统判断是 v3 评测结果快照 | 否。表内注明全部为虚构工单，要求专工不填写真实电厂、人员信息 |

- 未使用任何真实电厂运行记录、真实员工信息或个人隐私数据；不涉及人脸、医疗、金融账户、行踪轨迹或未成年人信息。
- 未爬取任何网站，未使用大赛评测集或测试集。
- 演示视频、截图和文档中只出现上述模拟数据。`docs/images/ui_*.png` 截图在演示数据库的临时副本上拍摄，其中多智能体调查由 DeepSeek 对虚构工单 HOLD-C01 实际运行一次得出。

## 评估结果的口径（重要）

项目文档中出现的所有效果数字（例如审核助手与审核结论的一致率、建议分平均误差、评分 v2 前后对比），**参照对象都是 `scripts/simulate_review.py` 的规则审核结论，数据都是模拟工单**。它们说明：

- 系统流程跑通，约束与护栏按设计生效；
- 智能体在“规则可判定”的场景下能找到正确证据并给出与规则一致的结论。

困难工单集上的数字（`scripts/eval_hard_cases.py`）口径相同：标准答案是同一套岗位规则作用在编写时标注的真实设备与等级上。这些工单是**有意挑选**的难例，数字只说明在这类情形下规则和智能体各自的表现，不代表整体准确率。初版标注中有 2 条等级在首轮评测后经复核修改，修改原因记录在该文件的 `label_note` 字段。

专工盲评（`scripts/score_blind_review.py`）的结果口径不同：参照对象是专工的判断，但题目仍是模拟工单；发布时须注明专工人数、背景以及专工之间的一致程度。目前尚未收到专工结果。

它们**不能**说明在真实电厂、真实审核人员面前的效果。获得真实结论需要真实工单与真实人工审核数据，这是后续验证计划的一部分。

## 外部大模型调用

- 默认使用 DeepSeek API（`deepseek-flash`）；也可换成通义千问、本地 Ollama 等 OpenAI 兼容服务。
- 发送给模型的内容只有模拟工单文本、评分明细和工具返回的模拟数据。
- API Key 只保存在本机 `llm.env.bat`（已加入 `.gitignore`，不进入仓库），仓库提供 `llm.env.example.bat` 占位模板。

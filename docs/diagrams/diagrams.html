按岗位调查：一条工单推给谁（openJiuwen，多个 ReActAgent）

一条工单只调查一次；各岗位代理并行；等级、证据、推送规程由代码校验和执行，智能体只读、不改任何分数。

① 定等级

推送用的等级 = 大模型等级复核（只能上调，须引用原文）。紧急程度智能体同时判断：查同机组近期工单、相似工单等级、部件知识库。
  • 两者都判紧急 → 快速通道
  • 只有智能体判紧急 → 疑似紧急，转值班人员确认
  • 智能体不能下调填报等级

② 岗位代理并行（每岗位一个）

只读本岗位职责、本岗位人员当前推送情况、本岗位同事对相似工单的审核。对两类人各给一个判断：
本机组：必须 / 参考 / 不推其他机组：必须 / 参考 / 不推
  • “可作参考”只用于本岗位核心设备发生在其他机组
  • 设备须在词表内并引用原文；证据须来自已调用的工具
  • 可上报更高等级（须引用原文），不能下调

③ 展开到每个人

同岗位、同机组关系的人结论相同，展开后与系统当前推送对比。
  • 可能漏推 / 可能多推 / 需人工判断

紧急快速通道等级复核判为紧急，或值班人员确认了疑似紧急：按推送规程立即推送本机组各专业，不等岗位代理
疑似紧急 → 值班人员只有紧急程度智能体（或岗位代理）判紧急时不自动推送，界面提示确认；确认后由代码重算，不再调用大模型

三个 ReActAgent 依次交接；最终结论由代码汇总并校验，不直接采信任何一个智能体的输出。
